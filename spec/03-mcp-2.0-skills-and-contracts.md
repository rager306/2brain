# Spec v1.0 — MCP 2.0 (`2026-07-28`), SEP-2640 Skills, Tasks, and Issue #7 Contracts

**Status:** Normative clean-room specification (Phase 0) · **License:** MIT
**Scope:** Complete MCP protocol surface, progressive disclosure, SEP-2640 Skills, MCP Tasks, stateless fail-closed write gate, Issue #7 data contracts (D01–D12), and ADR-0009 crash-safe outcome registry.

---

## 1. Protocol Support & Transports

The single `2brain` binary serves MCP over **stdio** (default) and optional **Streamable HTTP** (`--http 127.0.0.1:<port>`):

1. **MCP 2.0 (`2026-07-28`, Stateless Core / SEP-2575):**
   - No mandatory `initialize` handshake or sticky session ID; every JSON-RPC request is self-describing with `_meta["io.modelcontextprotocol/protocolVersion"] = "2026-07-28"` and `_meta["io.modelcontextprotocol/clientCapabilities"] = {...}` (and HTTP headers `Mcp-Method` / `Mcp-Name` on HTTP transport).
   - Responses carry `_meta["io.2brain/generation"]` (monotonically increasing `u64` snapshot generation) and cache hints (`ttlMs`, `cacheScope`).
2. **Legacy Compatibility (`2024-11-05`, `2025-03-26`, `2025-06-18`, `2025-11-25`):**
   - Standard `initialize` → `notifications/initialized` lifecycle for existing clients (`antigravity`, `hermes-agent`, Claude Code, Cursor).
3. **In-Process vs Daemon Execution:**
   - `2brain mcp <socket>` connects to `2brain daemon` over Unix socket (shared hot graph across multiple clients).
   - `2brain mcp --in-process <vault>` binds MCP directly to `tb-app` inside one process (zero IPC overhead).

## 3. Skills-over-MCP (`SEP-2640` / `io.modelcontextprotocol/skills`)

### 3.1. Capability Declaration

```json
{
  "capabilities": {
    "resources": {},
    "prompts": {},
    "extensions": {
      "io.modelcontextprotocol/skills": { "directoryRead": true },
      "io.modelcontextprotocol/tasks": {}
    }
  }
}
```

### 3.2. Protocol Methods & URI Scheme

- **`skills/list`**: returns lightweight skill descriptors with SHA-256 resource manifests and TTL caching:
  ```json
  {
    "skills": [
      {
        "uri": "skill://2brain/grounded-answer/SKILL.md",
        "frontmatter": {
          "name": "grounded-answer",
          "description": "Answer questions from revision-bound evidence bundles without fabrication"
        },
        "resources": [
          { "uri": "skill://2brain/grounded-answer/SKILL.md", "digest": "sha256:<hex>", "size": 2410 }
        ],
        "ttlMs": 300000,
        "cacheScope": "connection"
      }
    ]
  }
  ```
- **`skills/get`** (`{ "uri": "skill://..." }`): fetches a single skill's manifest and digests.
- **`resources/read`** (`{ "uri": "skill://..." }`) and **`resources/directory/read`**: lazily loads markdown instructions and references; clients verify bytes against `digest`.
- **Dual Catalog Sources:**
  1. **Built-in core skills (`skill://2brain/<name>/SKILL.md`):** `grounded-answer`, `safe-edit`, `cognitive-explore`, `contradiction-audit`, `session-handoff`.
  2. **Vault-authored skills (`skill://vault/<name>/SKILL.md`):** automatically projected from notes of `type: mcp.skill` and promoted `type: pattern` notes that declare `trigger` + `procedure` fields; digests automatically refresh on `Generation` advance.
- **Backward compatibility:** `prompts/list` (`recall`, `intake`, `handoff`) and `2brain://workflow/{answer-shape,write-gates}` remain served for legacy clients.

## 4. MCP Tasks (`io.modelcontextprotocol/tasks`) & Elicitation

- **Tasks:** heavy analytics (`tb_analyze_topology`, `tb_detect_gaps`, `tb_diff_graphs`, `tb_audit_contradictions`) return synchronously when cached for the current `Generation` (`< 50 ms`), or return a durable handle `{ taskId, status: "working", ttlMs }` queryable via `tasks/get` so long-running work never blocks `< 1 ms` reads.
- **Elicitation (`input_required`):** when supported by the client, ambiguous/irreversible actions (resolving conflicting claims `D11`, promoting a pattern to a skill, enabling production fences) may pause with a JSON Schema form request rather than guessing or silently failing.

## 5. Fail-Closed Write Gate (Stateless & Stateful)

1. **Precondition for modifying an existing file (`tb_write_file`, `tb_edit_file`, `tb_delete_file`):**
   - Caller MUST have performed a **complete, non-truncated** `tb_content` read (`truncated: false`). Partial/EOF reads NEVER arm a write (SEM-02).
   - **Stateful legacy mode:** verified via process-local `ReadLedger` + engine CAS `expected_hash`.
   - **Stateless MCP 2.0 mode:** `tb_content` emits an HMAC-SHA256 signed `read_receipt` (built via `rmcp::request-state` with zeroized key) binding `(principal, repo, path, sha256, whole_file=true, generation, expires_at)`. Mutating calls pass `expected_hash` + `read_receipt`; the server validates signature, whole-file flag, expiry, and current disk `expected_hash` atomically under the write lock.
2. **Audit log:** every allowed or denied mutation emits a hash-chained JSON audit event (`principal`, `tool`, `member`, `outcome`, `seq`, `prev`, `hash`).
3. **Self-documenting errors:** every refusal returns a structured `reason_code` (`prior_read`, `expected_hash_mismatch`, `stale`, `quota`, `conflict`, `outcome_unknown`, `not_enabled`, `policy_denied`) and a concrete `recovery_hint`.

## 6. Context Assembly (`tb_context`, Issue #7 D01–D06, AE24)

- **Bounded cascade:** exact/BM25 seed → bounded typed neighbors → conditional hydration → complete-bundle selection (AND inside an alternative, OR across alternatives; decisive exceptions preserved under budget) → criterion assessment.
- **Release Admission Gate (KTD5 / U5):** immediately before releasing the assembled `ContextPack`, verify that every read and a final generation/member probe agree on one `Generation` and active member eligibility. Any generation change or revocation blocks the entire bundle with zero partial text leaked.
- **Honest Uncertainty (`why`, KTD9 / R8):** every explanation dimension (`support`, `conflicts`, `supersession`, `missingness`) carries an explicit `Assessment` status (`available | assessed_empty | incomplete | unavailable | unassessed`); a failed conflict check MUST report `unavailable`, never `[]`.
- **Provider Egress Boundary (AE24):** supports `--policy` (`egress_policy`, `egress_destination`) so controlled hosts enforce destination eligibility before dispatch; ordinary clients receive explicit disclosure boundary metadata.

## 7. Durable Outcome Registry & Crash-Safe Quota Index (ADR-0009, G4)

- **Opt-in format fence:** `<state_root>/outcomes/registry.version` containing exactly `2brain.outcome-registry/v1\n`. Absent fence ⇒ legacy non-registered mode (`tb_mutation_outcome` answers `enabled: false, present: false, state: "unknown", replay: "absent"`).
- **Canonical request binding:** `request_id` (32 lowercase hex) bound once to SHA-256 of canonical `(verb, workspace, arguments, preconditions)`. Reusing an ID with different inputs fails closed (`conflict`).
- **Framed CRC-32 journal:** append-only `<root>/outcomes/<id[..2]>/<id>.journal` with transitions `Reserved → Prepared → Executing → Committed | Rejected | Compensating → Compensated` plus optional terminal `Response` frame (≤ 64 KiB) for exact idempotent replay (`replayed: true`).
- **Crash-safe O(1) quota usage index:**
  - `usage.json` (`2brain.outcome-usage/v1`, IEEE CRC-32 over canonical `schema:records:bytes`), published via `create_new(true)` unique temp file → `sync_all` → `rename` → `sync_dir`.
  - Write-ahead `usage.dirty` synced BEFORE creating/appending journals or writing tombstones, removed only AFTER `usage.json` is durable.
  - Exclusive workspace `registry.lock` (`fs4::fs_std::FileExt::lock_exclusive`) serializing mutations, background compaction, startup recovery, and pruning.
  - `prune_tombstones_to` scans ground truth on disk under `registry.lock` and unlinks `usage.json` before deleting tombstones (no stale-cache over-pruning, no `ENOSPC` deadlock).
  - All service files (`registry.lock`, `usage.dirty`, `usage.json`) validate `symlink_metadata` (regular files only) and never open existing paths with `create(true).truncate(true)`.
