experiment, not a benchmark, deployment, or claim about the served system.

`/tmp/sparx-research`; it was not installed or vendored into 2brain.

## Shipped mechanisms, ranked by expected value per unit of risk

Ranking is a qualitative judgment, not measured payoff. Items 1–5 are the
most promising *patterns* for bounded, offline investigation; none authorizes a
write or substitutes for the lane register.

1. **Independent small-graph oracle.** SCC tests compare actual component
   labels with mutually reachable node pairs on constructed and seeded random
   fixtures, plus a long path (`src/components/strong.rs:265-296`); separate
   k-truss references peel a simple graph and compare two algorithms across
   thread counts (`src/k_truss/oracle_test.rs:12-85`). Buys a different route
   to an answer and catches shared assumptions that invariant-only checks miss.
   Existing 2brain tests and measurement doctrine already use degradation and
   independent checks; this is a targeted complement, not a new authority.
2. **Explicit graph semantics.** Directed and undirected graph types restrict
   which algorithms compile; conversion modes distinguish collapse, per-arc,
   and mutual edges (`src/graph/direction.rs:5-15,82-135`; executable
   compile-fail examples at `:37-63`). Buys clarity about direction,
   multiplicity and what an algorithm actually counts. 2brain already has
   typed links and resolver semantics; a raw edge export cannot replace them.
3. **Incremental work by changed neighborhood.** HyperBall marks changed
   counters and skips nodes whose neighbors did not change
   (`src/centralities/hyper_ball.rs:889-895,962-1004`); tests compare skipping
   against computing all (`:1134-1164`). Buys less repeat work while retaining
   a direct unoptimized comparison. Existing candidate-set-first and visit
   counters address a related concern, not this particular algorithm.
4. **Derived artifact lifecycle and publication.** Derived-graph registries
   cascade invalidation (`src/graph/cache/impl_derive.rs:27-66`); temporary
   per-build files are built before being renamed, metadata last (`:477-533`).
   Buys reuse and reduces exposure to incomplete builds. This is a pattern to
   study, not a proven crash-consistent transaction: the multi-file renames,
   races and durability need independent tests. A second persistent graph
   cache must never become an alternative writer or authority.
5. **Cross-width and overflow checks.** Index capacities are checked before
   truncating representations (`src/graph/cache/mod.rs:222-248`); k-core
   tests compare index widths and check structural invariants
   (`src/k_core/batagelj_zaversnik.rs:458-466,504-510`). Buys smaller storage
   without silently accepting out-of-range values. The engine already uses
   compact search structures; no benefit follows without profiling its data.
6. **Iterative SCC and deterministic labels.** The SCC implementation uses
   explicit DFS and Tarjan stacks, with a symmetric-graph shortcut
   (`src/components/strong.rs:148-178`); labels are renumbered in node order
   (`:250-255`). Buys stack safety and stable labels for a fixed node order.
   An SCC is not a detector of every short cycle: a long cycle can be an SCC.
7. **Triangle intersection and k-core/truss peeling.** Sorted-neighbor merge
   counts triangles, including parallel-edge combinations
   (`src/k_truss/triangles.rs:172-176`); the k-core implementation offers
   selectable count widths (`src/k_core/batagelj_zaversnik.rs:17-20,79-108`).
   Buys density diagnostics, but directed typed wiki-links are not automatically
   an undirected simple graph; counts depend on the conversion chosen.
8. **Community detection and convergence choices.** Louvain offers Leiden
   refinement before aggregation (`src/communities/gve_louvain.rs:180-198`);
   directed Louvain alternates local moves and aggregation and describes
   timing-dependent parallel partitions (`src/communities/directed_louvain.rs:209-265`).
   Buys candidate clusters for inspection, not a semantic type or topic.
9. **Approximate reachability centrality.** HyperBall propagates HyperLogLog
   counters to estimate distances (`src/centralities/hyper_ball.rs:77-88,103-117`);
   exact counter-union comparisons with a GPU are tested where available
   (`:1723-1763`). Buys a bounded approximation on huge graphs; approximation,
   convergence cap, direction and GPU availability must be reported.
10. **Parallel weighted paths.** Delta stepping uses distance buckets,
    parallel relaxation and per-thread queues (`src/trails/delta_stepping.rs:1-12,85-94`).
    Buys parallel shortest paths under nonnegative finite weights; weighted
    graph distance is not automatically a measure of semantic relevance.
11. **Coarse relative performance checks.** Opt-in release tests compare work
    with a reference on the same machine (`tests/perf_regression.rs:1-9`),
    including an explicit ratio assertion (`:221-232`). Buys detection of
    large regressions, not universal machine independence or proof of real
    workload speed. The local measurement doctrine already requires stating
    the measured population, resolver and limits.

## Prose recommendations, not shipped 2brain behavior

- For a real graph question, first name direction, edge kinds, duplicates,
  self-loops, snapshot identity and resolver. A parser or a hand-supplied JSON
  graph measures only that input, not the workspace's resolved graph.
- Prefer an exact oracle on small fixtures to importing a whole static graph
  engine. Preserve 2brain's engine as the writer and its MCP fail-closed gate.
- Record decision thresholds before running any pilot. No sparx timing or
  thresholds are transferred to 2brain. Keep decisions and deployment state
  in their existing authorities, including the trajectory's lane register.

## Bounded adaptation: SCC partition oracle

**Tooling layer**, not product: `tools/scc_oracle.py` independently checks
candidate SCC labels against mutual reachability in a supplied JSON graph.
It is inspired by sparx's reference-test pattern, not a port or source copy.
It requires only Python's standard library, takes no implicit workspace path,
does not write, and opens neither a vault nor a socket. Delete the single file
to reverse it. Usage: `python3 tools/scc_oracle.py --selftest`, or
`python3 tools/scc_oracle.py fixture.json`. The file's docstring gives the
fixture schema. Exit 0 means the labels describe the supplied graph's SCC
partition; 1 means one or more mismatched node pairs; 2 means invalid input.
Labels can be arbitrarily named: membership, not spelling, is compared.

The self-test checks a cycle with a one-way tail, a self-loop and an isolated
component, then deliberately merges and splits components, checks a malformed
edge and the empty graph. It passed on 2026-11-17.

This proves those small cases only. It does **not** read or resolve 2brain content,
compare any actual engine output, test the live system, or establish a speed
benefit. Its all-sources traversal and pairwise comparison are deliberately
suitable only for small fixtures. SCC equality also cannot enforce a maximum cycle
length; do not use it as a write gate or as proof that no cycle of length ≤3 exists.

**Second adaptation, shipped in the engine (2026-11-17): `graph_health` names the
fragile joints.** `bridges` and `articulation_points` join the read, computed on the
undirected projection of the same resolved in-scope edges: parallel edges collapse
for the structure but a pair joined more than once is never reported as a bridge,
and self-loops are ignored. The algorithm is an iterative Tarjan lowlink, not a
port of sparx's parallel FAST-BCC — the question is borrowed, not the code. On a
frozen snapshot (1 228 nodes, 4 730 edges) the answer is **37 bridges and 57
articulation points**; the top articulation points are the topic maps
(`knowledge/memory-systems.md` 167, `knowledge/agentic-architecture.md` 158,
`knowledge/jev.md` 120), and the bridges are mostly a pattern note attached by a
single inbound link. The same read reports the projection's weave: **3 123
triangles and a transitivity of 0.1816** on that snapshot — the base is a set of
linked chains more than a family of mutually citing notes, which is the number an
intake pass can move. That is a diagnostic the base did not have, and it is
measured on a copy, never on the live vault. The "do not adopt" table below still
stands: SCC is not a short-cycle policy, and none of these numbers is a write gate.

## Do not adopt now, and what would change each verdict

| Do not adopt | Reason | Smallest falsifiable experiment |
|---|---|---|
| sparx as 2brain's graph store, writer, or persistent second authority | Static cached analytics do not implement typed Markdown resolution, mutations or the existing fail-closed gate; two authorities can drift. | On one frozen synthetic workspace, compare a resolved export and its version identity before/after a mutation; any mismatch rejects it. Even a match is not authorization to replace the writer. |
| Any SCC, cluster or benchmark result as a write-path gate | SCCs do not by themselves encode a short-cycle policy; cluster labels are not semantic validation. | On a fixture with a 2-cycle, 3-cycle and 4-cycle, test the proposed rule against a separately enumerated cycle oracle; a false allow or false block rejects it. No live writes. |
| A parallel graph-analysis lane registry or autonomous orchestration | Competes with the existing lane register and session state; sparx is a library, not evidence for an orchestration replacement. | Reproduce a documented missed handoff on two isolated fixture lanes; compare current register and a proposed replacement with one authority and no extra writer. No measured failure, no replacement. |
| GPU/HyperBall or approximate centrality in serving | Added runtime, approximation and operational cost without a demonstrated bottleneck or relevance gain. | On a frozen exported fixture, compare exact versus approximate top-k and wall time, report error, memory and setup; reject if no predeclared gain at acceptable error. |
| Community detection as automatic semantic topics | Modularity clusters depend on direction, weights and timing; they do not validate meaning or frontmatter. | Blindly review cluster suggestions on a frozen, resolved sample against predeclared labels and a simple baseline; reject if it adds no actionable, correctly supported suggestions. |
| Copying derived-cache publication as a durability guarantee | Metadata-last publication alone does not establish atomicity, crash durability or safe invalidation. | In a temporary directory, interrupt builds at each rename and race two builders and invalidation; reject if any reader sees a mixed or stale completed artifact. |
