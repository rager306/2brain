# Бриф для Hermes: работа с волтом через Rust-адаптер

Этот документ самодостаточен: в нём есть всё, что нужно сессии Hermes, у которой нет
никакого предыдущего контекста.

## 1. Что такое волт и что за серверы

Волт — git-репозиторий `/root/vault` с типизированными markdown-заметками: у каждой
заметки есть frontmatter с полем `type`, а связи между заметками — это `[[wiki-links]]`
и блочные якоря `^block-id`. Поверх волта работает движок `au-engine`: он единственный,
кто пишет в волт, и он держит индекс типов, ссылок и диагностик.

Мирволт (workspace) — это несколько репозиториев, смонтированных вместе. У волта сейчас
7 участников: `vault`, `mcp-bundle`, `au-mcp`, `au-mcp-core`, `au-mcp-sdk`,
`au-mcp-adapter-cc`, `au-mcp-adapter-codex`.

К движку можно подключиться двумя разными MCP-серверами, и они НЕ взаимозаменяемы по
именам инструментов:

| сервер | инструменты называются | что это |
|---|---|---|
| `arsumbris` | `mcp__au_overview`, `mcp__au_content`, … | старый путь: Python-мост к Node-демону. Отвечает спроецированными, «причёсанными» ответами |
| `arsumbris-rs` | `mcp__arsumbris-rs__au_overview`, … | новый путь: Rust-адаптер прямо к сокету движка. Отвечает объектом движка под ключом самого чтения |

**Для этой задачи используется только `arsumbris-rs`.** Если инструмент не найден под
этим именем — задача не выполнена, а не «сделана другим способом».

Сокет движка: `/root/.arsumbris/au-engine/run/adcfe8680a485529.sock`
Бинарь адаптера: `/root/arsumbris/au-mcp-rs/target/release/au-mcp-rs`

## 2. Правила, которые нельзя нарушать

1. **Перед любой записью — чтение того же пути.** `au_write_file`, `au_edit_file`,
   `au_delete_file` требуют `expected_hash` — ровно ту 16-символьную hex-строку, которую
   вернул `au_content` для этого файла. Хеш обязателен; выдуманный или устаревший хеш
   отклоняется без записи.
2. **Хеш живёт до первой записи.** После успешной записи записанное чтение
   аннулируется: чтобы писать снова, нужно снова прочитать файл.
3. **`outcome_unknown` — не ошибка и не повод повторять.** Если ответ на запись потерян,
   инструмент отвечает `outcome_unknown` и говорит, что мутация могла примениться.
   Повторная отправка применит её дважды. Правильный ход — `au_reconcile` с тем же
   путём и `expected_hash`, который должна была дать запись.
4. **`au_reconcile` принимает только настоящий дайджест** (16 hex-символов) или
   `expect_absent: true` для удаления. Если дайджеста нет — читайте файл через
   `au_content` и сравнивайте текст, а не отправляйте `"null"`.
5. **Несколько файлов меняются одним `au_batch`**, а не серией одиночных записей: батч
   либо применяется целиком, либо не применяется вовсе. Каждая операция в батче несёт
   свой `expected_hash` и требует своего предварительного чтения.
6. **Перед откатом коммита — `au_rollback_preview`.** Он ничего не меняет: показывает,
   какие пути затронет откат (`restore` или `delete`), безопасны ли они (`safe`) и не
   переписал ли их кто-то позже.
7. **Не поллить.** `au_files` в цикле — неправильно; `au_watch {timeout_ms}` ждёт
   изменения и возвращает дельту, таймаут — это нормальный ответ, а не ошибка.
8. **Пути — относительно участника.** У `au_content`, `au_write_file` и остальных есть
   `repo` (имя участника) и `path` (путь внутри него, без `..`). Абсолютный путь
   отклоняется.
9. **Не пишите в `/root/vault` ничего, кроме явно названного в задаче файла.**

## 3. Полезная карта инструментов (35 без грантов, +16 мутаций с грантом)

Чтение: `au_overview` (участники, топология, счётчики) · `au_members` (корни
участников) · `au_types`, `au_type` (словарь типов, один тип с полями) · `au_type_tree`
· `au_hubs` (самые связанные заметки) · `au_diagnostics` (проблемы волта) · `au_files` ·
`au_content` (текст + hash + commit) · `au_frontmatter` · `au_anchors` (заголовки файла) ·
`au_block_ids` · `au_references` · `au_neighborhood` · `au_grep` (литеральный поиск по
тексту) · `au_graph_health` (циклы, тупики, битые ссылки) · `au_rollback_preview` ·
`au_search_tools` / `au_describe_tool` (найти инструмент по описанию).

Запись (только с грантом): `au_write_file`, `au_edit_file`, `au_delete_file`,
`au_create_file`, `au_batch`, `au_assign_block_id`, `au_rename_block_id`, `au_rename`,
`au_rename_type`, `au_inline`, `au_promote`, `au_reconcile`.

## 4. Задача 1: только чтение (без грантов)

Промпт, который надо дать Hermes:

    Используй только инструменты сервера arsumbris-rs (имена начинаются с
    mcp__arsumbris-rs__), сервер arsumbris не трогай. Ответь мне на русском:
    1) какие участники смонтированы в волте и кто из них editable;
    2) пять заметок волта с наибольшим числом ссылок — путь и refs_total;
    3) у самой связанной из них — её frontmatter и список заголовков;
    4) есть ли в волте диагностики.

Чеклист (проверяет оператор, не Hermes):

- первый вызов — `au_overview` или `au_members`, а не догадка о структуре;
- в ответе `au_content` присутствуют `hash` и `commit` — это признак Rust-адаптера;
  мост отдаёт текст без хеша;
- нет ни одного `unknown tool`, ни одного `policy/…`;
- если Hermes сомневался в выборе инструмента, он вызывал `au_search_tools` — это
  штатное поведение, а не ошибка.

## 5. Задача 2: одна запись на выбрасываемом пути (нужен грант)

Требует, чтобы адаптер был запущен с `--allow-mutations` (см. раздел 6).

Промпт:

    Используй только инструменты сервера arsumbris-rs. Создай в волте файл
    inbox/adapter-write-test.md с типом note, заголовком «Adapter write test» и одной
    строкой текста «written through the Rust adapter». Затем прочитай его обратно и
    назови его hash и commit. Не меняй никакие другие файлы. В конце одной строкой
    скажи, что именно ты сделал и чем это подтверждается.

Чеклист:

1. Запись — **один** коммит движка:
   `git -C /root/vault log -1 --stat` показывает ровно один файл.
2. Обратное чтение возвращает тот же текст; `hash` в ответе совпадает с тем, что
   вернул `au_content` после записи.
3. **Повторная запись без свежего чтения отклоняется** с сообщением, начинающимся на
   `policy/prior_read`. Это и есть гейт: он требует чтения перед каждой записью.
   Попросите Hermes «попробуй записать ещё раз тем же хешем» — ожидаемый ответ: отказ,
   а не вторая запись.
4. Если Hermes увидел `outcome_unknown` — он обязан был вызвать `au_reconcile`, а не
   повторять запись. Проверяется по транскрипту.

Уборка:

    git -C /root/vault rm inbox/adapter-write-test.md
    git -C /root/vault -c user.name=hermes -c user.email=hermes@local commit -m "test: remove adapter write test"

## 6. Операторские шаги (делает человек, не Hermes)

Файл конфигурации: `~/.hermes/config.yaml`, раздел `mcp_servers:`.

**Шаг 1 — read-only.** Добавить рядом с существующим `arsumbris` (не заменяя его):

    arsumbris-rs:
      type: stdio
      command: /root/arsumbris/au-mcp-rs/target/release/au-mcp-rs
      args:
        - /root/.arsumbris/au-engine/run/adcfe8680a485529.sock

Отступы: два пробела на уровень, то есть `arsumbris-rs:` на том же уровне, что и
`arsumbris:`, а его ключи — на два пробела глубже.

Затем **начать новую сессию Hermes**: конфиг читается при старте, старая сессия его не
подхватит.

Ожидаемо в списке инструментов: 35 штук с префиксом `mcp__arsumbris-rs__`, и среди них
НЕТ `au_write_file`, `au_batch`, `au_create_file`.

**Шаг 2 — с грантом.** В тот же блок добавить строку аргументов:

    args:
      - /root/.arsumbris/au-engine/run/adcfe8680a485529.sock
      - --allow-mutations

Снова новая сессия. Теперь инструментов 51: 35 чтений и 16 мутаций.

**Шаг 3 — сравнение до и после (read-only, можно в любой момент):**

    cd /root/arsumbris/au-mcp-rs
    python3 scripts/live_parity.py

Ожидаемый результат — пять строк `identical` и `PASS`. Коды выхода: `0` — сошлось,
`1` — расхождение, `2` — не смог сравнить (это не успех).

**Откат:** удалить блок `arsumbris-rs` из `~/.hermes/config.yaml` и начать новую сессию.
Движок, волт и Node-стек при этой процедуре не менялись, поэтому возврат мгновенный.

## 7. Что прислать назад

- транскрипт сессии, если какой-то вызов инструмента упал;
- вывод `python3 scripts/live_parity.py` после прогона;
- текст промпта и то, что Hermes ответил вместо ожидаемого.

Самая полезная жалоба — «он хотел сделать X, и ни один инструмент не дал X»: это
описание пробела в поверхности, а не ошибки клиента.
